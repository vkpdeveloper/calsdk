Here's a feature request that sounds like an afternoon's work: show the times when Ana (on Google Calendar) and Raj (on Outlook) are both free for 30 minutes next week, during Berlin working hours.

Merging two lists of busy times is the easy part. The hard part is getting a busy time you can trust from each provider, because the three big calendar APIs each answer "when is this person busy?" differently, and one of them barely answers it at all.

## How does Google Calendar report busy time?

Google is the easy one. You [`POST /freeBusy`](https://developers.google.com/calendar/api/v3/reference/freebusy/query) with a window and a list of calendar ids, and get back busy ranges per calendar:

```json
{
  "calendars": {
    "primary": {
      "busy": [{ "start": "2026-11-09T08:30:00Z", "end": "2026-11-09T09:00:00Z" }]
    },
    "team@example.com": {
      "errors": [{ "domain": "global", "reason": "notFound" }]
    }
  }
}
```

There are two things to notice. First, Google has already applied its own rules: an event marked "show as free" ([`transparency: "transparent"`](https://developers.google.com/calendar/api/v3/reference/events)) isn't in there, and it works for calendars the user can only see as free/busy, where listing events would give you nothing. Second, a failure doesn't fail the request. A calendar that wasn't found, or that isn't shared with you, comes back with an `errors` array and no `busy` key. If your code reads `busy ?? []`, that calendar now looks completely free. That isn't an edge case. It's the default way to get it wrong.

The only limit worth knowing is that one request covers [at most 50 calendars](https://developers.google.com/calendar/api/v3/reference/freebusy/query), so a big team needs batching.

## Why not use Outlook's getSchedule?

Microsoft Graph's free/busy endpoint, [`getSchedule`](https://learn.microsoft.com/en-us/graph/api/calendar-getschedule), doesn't work for personal Microsoft accounts. You give it email addresses and a window, and it gives you back an `availabilityView` string with one digit per time slot:

```json
{ "scheduleId": "raj@contoso.com", "availabilityView": "000220130" }
```

`0` is free, `1` tentative, `2` busy and `3` out of office. The slot length ([`availabilityViewInterval`](https://learn.microsoft.com/en-us/graph/api/calendar-getschedule)) defaults to 30 minutes and goes from 5 to 1440. There's also a `scheduleItems` array with the actual start and end of each item, which is what you want: the digit string rounds everything to the slot length.

The catch is in the [permissions table](https://learn.microsoft.com/en-us/graph/api/calendar-getschedule#permissions), which marks personal Microsoft accounts as not supported. If your users sign in with an outlook.com or hotmail.com address, `getSchedule` is not an option. On a busy shared calendar it also gives up past 1000 entries in the window.

The other route works for every account: list the events with [`calendarView`](https://learn.microsoft.com/en-us/graph/api/user-list-calendarview), which expands recurring series into occurrences on the server, and work out busy time yourself. That's what calsdk does for Outlook. It does mean you now own the rules Graph would have applied for you, starting with `showAs`. The [event resource](https://learn.microsoft.com/en-us/graph/api/resources/event) lists six values (`free`, `tentative`, `busy`, `oof`, `workingElsewhere` and `unknown`), and you have to decide which ones block time.

Interestingly, `getSchedule` writes "working elsewhere" as `0`, which is free, [for backward compatibility](https://learn.microsoft.com/en-us/graph/api/resources/scheduleinformation). I went the other way and count everything except `free` as busy. Someone working from another office, or tentatively holding a slot, usually doesn't want a stranger booking it.

Time zones need care too. Graph names zones [the Windows way](https://learn.microsoft.com/en-us/graph/api/resources/datetimetimezone), like `"Pacific Standard Time"`, not `"America/Los_Angeles"`, and a `Prefer: outlook.timezone` header changes which zone it writes times in. For busy time, ask for UTC with `Prefer: outlook.timezone="UTC"` and you skip the mapping entirely.

## How do you get busy time from iCloud and CalDAV?

List the events with a `calendar-query` REPORT and compute busy time yourself. CalDAV, the protocol behind iCloud, Fastmail, Nextcloud, Zoho and most self-hosted calendars, does define a [`free-busy-query` REPORT](https://datatracker.ietf.org/doc/html/rfc4791#section-7.10), but whether it works depends on the server.

I didn't want a feature that works on some servers and not others, so calsdk treats CalDAV the same way as Outlook. The [`calendar-query` REPORT](https://datatracker.ietf.org/doc/html/rfc4791#section-7.8) takes a time range:

```xml
<C:calendar-query xmlns:D="DAV:" xmlns:C="urn:ietf:params:xml:ns:caldav">
  <D:prop><D:getetag/><C:calendar-data/></D:prop>
  <C:filter>
    <C:comp-filter name="VCALENDAR">
      <C:comp-filter name="VEVENT">
        <C:time-range start="20261108T000000Z" end="20261115T000000Z"/>
      </C:comp-filter>
    </C:comp-filter>
  </C:filter>
</C:calendar-query>
```

What comes back is raw iCalendar text, and everything is now your problem. Recurring events arrive as one `VEVENT` with an `RRULE` and its exceptions, so you expand the occurrences yourself. Servers read floating times and all-day dates in a zone of their choosing, so calsdk asks for a day of slack on either side and filters the results itself. Busy or free is the [`TRANSP` property](https://datatracker.ietf.org/doc/html/rfc5545#section-3.8.2.7) (`TRANSPARENT` means free), and cancelled occurrences have [`STATUS:CANCELLED`](https://datatracker.ietf.org/doc/html/rfc5545#section-3.8.1.11).

Some servers have extra quirks. Zoho answers a calendar query without the event data, so every event has to be fetched again with a [`calendar-multiget`](https://datatracker.ietf.org/doc/html/rfc4791#section-7.9). If one of those fetches fails, it's tempting to skip that event. Don't: a missing event is time that looks free. calsdk fails the whole listing instead.

## How do Google, Outlook and CalDAV compare?

Only Google gives you a [free/busy answer](https://developers.google.com/calendar/api/v3/reference/freebusy/query) that works for every account and server. Outlook's [`getSchedule`](https://learn.microsoft.com/en-us/graph/api/calendar-getschedule) doesn't take personal accounts, and calsdk doesn't rely on CalDAV's [`free-busy-query`](https://datatracker.ietf.org/doc/html/rfc4791#section-7.10) report, so for both it lists events and computes busy time itself:

| Provider                | Free/busy endpoint                                                                         | Catch                                                                | What calsdk uses                                           |
| ----------------------- | ------------------------------------------------------------------------------------------ | -------------------------------------------------------------------- | ---------------------------------------------------------- |
| Google Calendar         | [`POST /freeBusy`](https://developers.google.com/calendar/api/v3/reference/freebusy/query) | 50 calendars per request; unreadable calendars come back as `errors` | The free/busy endpoint                                     |
| Outlook                 | [`getSchedule`](https://learn.microsoft.com/en-us/graph/api/calendar-getschedule)          | No personal accounts; fails past 1000 entries in the window          | `calendarView`, then computes busy time from `showAs`      |
| iCloud and other CalDAV | [`free-busy-query`](https://datatracker.ietf.org/doc/html/rfc4791#section-7.10) REPORT    | Depends on the server                                                | `calendar-query`, then expands series and reads `TRANSP`   |

## What catches people out on every provider?

All-day events, private events, declined invitations and rate limits. Each one is easy to get wrong, and most of the mistakes show busy time as free.

All-day events are dates, not instants. A holiday on November 9 means November 9 in the calendar's own time zone, so to turn it into a busy range you need that zone, which you only get from the calendar list. If you can't get it, the safe choice is to block the day in every zone, from UTC+14 through UTC-12. That covers more than a day, but it never shows a holiday as free.

Private events still block time. You won't see the title, but you need the range.

Declined invitations are a judgment call. The event fallback in calsdk only looks at the event's own free/busy flag and whether it's cancelled, not at your RSVP. So a declined invite that stays on the calendar still counts as busy. That's a choice, and it errs the same way as everything else: better to hide a free slot than to offer a taken one.

Rate limits are real once you list a week of events for 20 people. [Google](https://developers.google.com/calendar/api/guides/quota) answers `403` or `429` with `usageLimits` when you go over its quota, and [Microsoft Graph](https://learn.microsoft.com/en-us/graph/throttling) answers `429` with a `Retry-After` header. Back off and retry, and keep the window as small as the feature allows.

## How do you merge busy times without double booking?

Merge every calendar's busy ranges into one sorted list, then keep each candidate slot inside working hours that overlaps none of them. With trustworthy busy ranges in hand, that takes three steps:

1. Put every busy range from every calendar into one list, clip it to the window, sort by start and merge ranges that overlap or touch.
2. Walk candidate start times (every 15 minutes, say) inside working hours, in the organizer's time zone.
3. Keep a candidate if `[start, start + duration)` doesn't overlap any merged range.

Working hours need more care than they seem to. "9 to 5 in Berlin" is a different UTC range on either side of a daylight saving change, and on the day the clocks spring forward an hour of wall-clock time simply doesn't exist. calsdk places slots on the local wall clock within each stretch of constant UTC offset, so the grid stays on the hour after the change and the missing hour gets no slots.

The important decision is what to do when one calendar can't be read. Remember Google's [per-calendar `errors`](https://developers.google.com/calendar/api/v3/reference/freebusy/query). If Raj's calendar comes back with an error and you carry on with Ana's alone, every slot you show is a guess about Raj. A booking page that confidently offers a time that clashes is worse than one that says "couldn't check Raj's calendar". So `findFreeTime` fails closed: it throws `FreeBusyUnavailableError`, with the `provider` and `calendarId`, rather than return slots that might clash.

## How does calsdk find free time?

calsdk finds free time with two functions. `getFreeBusy` returns merged busy ranges for one provider, using Google's endpoint where it exists and listing events elsewhere, with a `compatibility` warning when it falls back. `findFreeTime` takes calendars from any mix of providers and returns the slots:

```ts
import { findFreeTime, FreeBusyUnavailableError } from '@cal-sdk/core';
import { icloud } from '@cal-sdk/caldav';
import { google } from '@cal-sdk/google';
import { microsoft } from '@cal-sdk/microsoft';

try {
  const { slots, warnings } = await findFreeTime({
    calendars: [
      { calendar: google({ accessToken: anaToken }) },
      { calendar: microsoft({ accessToken: rajToken }), calendarIds: ['primary', roomCalendarId] },
      { calendar: icloud({ appleId, appPassword }) },
    ],
    timeMin: '2026-11-09T00:00:00Z',
    timeMax: '2026-11-14T00:00:00Z',
    duration: 30,
    workingHours: { start: '09:00', end: '17:00', timeZone: 'Europe/Berlin' },
  });
  // slots: [{ start: '2026-11-09T08:00:00.000Z', end: '2026-11-09T08:30:00.000Z' }, ...]
} catch (error) {
  if (FreeBusyUnavailableError.isInstance(error)) {
    // Tell the user which calendar couldn't be read, instead of guessing.
  }
  throw error;
}
```

Slots come back as UTC instants, ready to show in each viewer's own zone. The [free time guide](/docs/guides/free-time) covers slot intervals, overlapping slots and booking the one the user picks.

If you want to poke at it without connecting a real account, the [quickstart](/docs/quickstart) runs against an in-memory calendar in a couple of minutes.

## FAQ

### Does Outlook have a free/busy API?

Yes: Microsoft Graph's [`getSchedule`](https://learn.microsoft.com/en-us/graph/api/calendar-getschedule). It doesn't support personal Microsoft accounts (outlook.com and hotmail.com), and it gives up past 1000 entries in the window. Listing events with `calendarView` and computing busy time yourself works for every account.

### Does iCloud support free/busy queries?

iCloud speaks CalDAV, and [RFC 4791](https://datatracker.ietf.org/doc/html/rfc4791#section-7.10) defines a `free-busy-query` REPORT, but support varies between CalDAV servers. Listing events with a `calendar-query` REPORT and computing busy time yourself works the same on every server.

### Should tentative and declined events count as busy?

Count everything except events marked "show as free" as busy, including tentative ones. calsdk also treats a declined invite that is still on the calendar as busy, because offering a taken slot is worse than hiding a free one.

### What should happen when one calendar can't be read?

Fail and say which calendar it was. Slots computed without that calendar are guesses that can clash. calsdk's `findFreeTime` throws `FreeBusyUnavailableError` with the provider and calendar id.

### How many calendars can one Google freeBusy request check?

Up to 50 calendars per request, according to the [freeBusy reference](https://developers.google.com/calendar/api/v3/reference/freebusy/query). Batch the request for larger teams.
