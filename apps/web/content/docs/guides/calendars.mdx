Most accounts hold more than one calendar: the user's own, a shared team calendar, someone's holidays. When your app needs to put an event somewhere other than the default, or let the user choose where it goes, start with `listCalendars`:

```ts
import { listCalendars } from '@cal-sdk/core';

const { calendars } = await listCalendars({ calendar });

for (const item of calendars) {
  console.log(item.id, item.name, item.isPrimary, item.accessRole, item.timeZone);
}
```

Exactly one calendar in the list has `isPrimary: true`.

## What does the `'primary'` calendar id mean?

`'primary'` is the user's default calendar. Every function that takes a `calendarId` defaults to it, and every provider resolves it for you, so you often don't need the list at all. Pass a `calendarId` only when you want a different calendar:

```ts
const { calendars } = await listCalendars({ calendar });
const team = calendars.find((item) => item.name === 'Team');

if (team) await createEvent({ calendar, calendarId: team.id, event });
```

What counts as the default depends on the provider. A CalDAV server names its default in the [`schedule-default-calendar-URL`](https://datatracker.ietf.org/doc/html/rfc6638#section-9.2) property. Booking and meeting tools don't have calendars in the usual sense: [Cal.com](https://cal.com/docs/api-reference/v2/event-types/list-event-types) has event types, while [Calendly](https://developer.calendly.com/api-docs/calendly-api/scheduled-events/list-scheduled-events) and [Zoom](https://developers.zoom.us/docs/api/meetings/) have scheduled meetings. calsdk maps what each one does have:

| Provider        | `'primary'` is                                                  |
| --------------- | --------------------------------------------------------------- |
| Google, Outlook | The account's default calendar                                  |
| CalDAV          | The server's default calendar for invitations, or else the first calendar that holds events |
| Cal.com         | Every booking of the user. Each event type is another calendar, with the event type id as its id |
| Calendly, Zoom  | Every meeting the user hosts. There are no other calendars      |
| ICS             | The feed                                                        |

## Which calendars can a user write to?

A user can write to the calendars whose `accessRole` is `owner` or `writer`, so check it before you offer a calendar as somewhere to save events. `reader` can only read events. A `freeBusyReader` sees nothing but busy times, so ask for those with [`getFreeBusy`](/docs/guides/free-time) instead of listing events.

To create the event once the user has picked a calendar, pass its `id` as `calendarId` to [`createEvent`](/docs/guides/write-events).
