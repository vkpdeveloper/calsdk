The [shared event shape](/docs/concepts/events) covers what every calendar has in common, and the order a booking came from isn't one of those things. For anything provider-specific, like tagging a Google event with its order id or setting Outlook's categories, pass `providerOptions` and read `providerMetadata`. Both are keyed by provider id, and both are typed by the provider you pass.

## Tag an event with an order id

This Google event carries the order it came from, and reads it back from `providerMetadata`:

```ts
import { createEvent } from '@cal-sdk/core';
import { google } from '@cal-sdk/google';

const calendar = google({ accessToken });

const { event } = await createEvent({
  calendar,
  event: {
    title: 'Order 42 handover',
    start: { dateTime: '2026-11-09T15:00:00Z', timeZone: 'UTC' },
    end: { dateTime: '2026-11-09T15:30:00Z', timeZone: 'UTC' },
  },
  providerOptions: {
    google: {
      guestsCanModify: true,
      extendedProperties: { private: { orderId: '42' } },
    },
  },
});

event.providerMetadata?.google?.extendedProperties?.private?.orderId; // '42'
```

## How are provider options type-checked?

TypeScript checks `providerOptions` against the provider you pass as `calendar`, so your editor knows which options exist. A typo, an option the provider doesn't take for this function, or another provider's key is a type error:

```ts
await createEvent({
  calendar, // google(...)
  event: input,
  providerOptions: {
    // Type error: Google has no `guestsCanModfy` option.
    google: { guestsCanModfy: true },
  },
});
```

Providers check options at runtime too, because options don't always come from code TypeScript has seen. A wrong value, such as a string where Google's [`guestsCanModify`](https://developers.google.com/workspace/calendar/api/v3/reference/events/insert) wants a boolean, throws `InvalidArgumentError` before any request. An unknown key is dropped with an `unsupported` warning rather than failing the call.

Often you don't know the provider at compile time, because a function returns Google or Outlook depending on what the user connected. When the provider type is a union like that, each provider's key is allowed, and at runtime each provider reads only its own:

```ts
await createEvent({
  calendar, // GoogleCalendarProvider | MicrosoftCalendarProvider
  event,
  providerOptions: {
    google: { guestsCanModify: true },
    microsoft: { importance: 'high' },
  },
});
```

## Which options does each provider accept?

Google, Outlook, Cal.com and Calendly accept options, each on certain functions only: for example `guestsCanModify` on Google creates and updates, or `categories` on Outlook. CalDAV, Zoom, ICS and the mock take none, and an option on any other function is a type error:

| Provider    | Functions                                   | Options |
| ----------- | ------------------------------------------- | ------- |
| `google`    | `createEvent`, `updateEvent`                | `guestsCanModify`, `guestsCanInviteOthers`, `guestsCanSeeOtherGuests`, `extendedProperties` |
| `google`    | `listEvents`                                | `eventTypes` |
| `microsoft` | `createEvent`, `updateEvent`                | `showAs`, `importance`, `categories`, `transactionId` |
| `microsoft` | `syncEvents`                                | `timeMin`, `timeMax` |
| `calcom`    | `createEvent`                               | `eventTypeId`, `metadata`, `allowConflicts`, `allowBookingOutOfBounds` |
| `calcom`    | `updateEvent`                               | `reschedulingReason`, `allowConflicts`, `allowBookingOutOfBounds` |
| `calcom`    | `deleteEvent`                               | `cancellationReason` |
| `calendly`  | `createEvent`                               | `eventType` (required), `location` |
| `calendly`  | `deleteEvent`                               | `reason` |

Each option maps to a field or parameter of the provider's own API, so its official docs say what each value does: Google's [`events.insert`](https://developers.google.com/workspace/calendar/api/v3/reference/events/insert) and [`events.list`](https://developers.google.com/workspace/calendar/api/v3/reference/events/list), the Microsoft Graph [event resource](https://learn.microsoft.com/en-us/graph/api/resources/event) and [calendar view delta](https://learn.microsoft.com/en-us/graph/api/event-delta), Cal.com's [create](https://cal.com/docs/api-reference/v2/bookings/create-a-booking), [reschedule](https://cal.com/docs/api-reference/v2/bookings/reschedule-a-booking) and [cancel](https://cal.com/docs/api-reference/v2/bookings/cancel-a-booking) booking endpoints, and Calendly's [Create Event Invitee](https://developer.calendly.com/api-docs/calendly-api/scheduled-events/create-event-invitee) and [Cancel Event](https://developer.calendly.com/api-docs/calendly-api/scheduled-events/create-scheduled-event-cancellation).

## What metadata does each provider return? [#what-each-provider-returns]

Events from five providers carry `providerMetadata` under their own key. CalDAV, ICS and the mock return none:

| Provider    | `providerMetadata` on events |
| ----------- | ---------------------------- |
| `google`    | `iCalUID`, `eventType`, `extendedProperties` |
| `microsoft` | `showAs` (Outlook's own, such as `'oof'`), `importance`, `categories`, `iCalUId` |
| `calcom`    | `bookingId`, `eventTypeId`, `status`, `rescheduledFromUid`, `metadata` |
| `calendly`  | `uri`, `eventType` |
| `zoom`      | `uuid`, `occurrenceId` |

Outlook's `showAs` metadata keeps the value from the [Graph event resource](https://learn.microsoft.com/en-us/graph/api/resources/event), such as `'oof'` (out of office) or `'tentative'`, which the shared `showAs` reduces to busy or free. Each [provider page](/docs/providers) explains its options.
