---
title: Overview
description: One TypeScript API for Google Calendar, Outlook, iCloud, Zoom, Cal.com, Calendly, CalDAV and ICS feeds.
---

calsdk gives your app one set of functions and one event shape for every calendar. You create a provider, such as `google({ accessToken })`, and pass it to plain functions like `listEvents` and `createEvent`. Switching calendars changes the provider line and nothing else.

```ts
import { listEvents } from 'calsdk';
import { google } from '@calsdk/google';

const calendar = google({ accessToken: () => getFreshAccessToken() });

const { events } = await listEvents({
  calendar,
  timeMin: '2026-11-01T00:00:00Z',
  timeMax: '2026-12-01T00:00:00Z',
});
```

When a provider cannot do part of a request, calsdk tells you: the call returns `warnings`, or throws `UnsupportedFunctionalityError` when going ahead would save something other than what you asked for. It never quietly changes your data.

## Providers

| Package             | Calendar                                                 |
| ------------------- | -------------------------------------------------------- |
| `@calsdk/google`    | [Google Calendar](/docs/providers/google)                |
| `@calsdk/microsoft` | [Microsoft Outlook](/docs/providers/microsoft), through Microsoft Graph |
| `@calsdk/caldav`    | [iCloud, Zoho Calendar and any CalDAV server](/docs/providers/caldav) |
| `@calsdk/calcom`    | [Cal.com](/docs/providers/calcom) bookings               |
| `@calsdk/calendly`  | [Calendly](/docs/providers/calendly) meetings            |
| `@calsdk/zoom`      | [Zoom](/docs/providers/zoom) meetings                    |
| `@calsdk/ics`       | [ICS feeds](/docs/providers/ics), read only              |
| `@calsdk/mock`      | [An in-memory calendar](/docs/providers/mock) for tests  |

The [provider comparison](/docs/providers) shows what each one supports.
