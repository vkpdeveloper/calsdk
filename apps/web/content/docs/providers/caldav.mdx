description: Read and write iCloud, Zoho Calendar, Fastmail, Nextcloud, Radicale and any other CalDAV server.

```npm
npm install calsdk @calsdk/caldav
```

One package covers every CalDAV server (RFC 4791), with shortcuts for iCloud and Zoho.

```ts tab="iCloud"
import { icloud } from '@calsdk/caldav';

// iCloud needs an app-specific password, made at account.apple.com under Sign-In and Security.
const calendar = icloud({
  appleId: 'me@icloud.com',
  appPassword: process.env.ICLOUD_APP_PASSWORD!,
});
```

```ts tab="Zoho"
import { zoho } from '@calsdk/caldav';

// The account's password, or an app-specific password when two-factor authentication is on.
const calendar = zoho({
  email: 'me@example.com',
  password: process.env.ZOHO_APP_PASSWORD!,
});
```

```ts tab="Any CalDAV server"
import { caldav } from '@calsdk/caldav';

const calendar = caldav({
  serverUrl: 'https://caldav.fastmail.com/dav/',
  username: 'me@fastmail.com',
  password: process.env.FASTMAIL_APP_PASSWORD!,
});
```

Then use it like any other provider:

```ts
const { calendars } = await listCalendars({ calendar });
const { events } = await listEvents({ calendar, timeMin, timeMax });
```

Zoho accounts outside the US data center pass the CalDAV address Zoho Calendar shows under Settings, Synchronize, CalDAV as `serverUrl`.

## Supports

All-day and recurring events (scopes `this` and `all`), attendees, etags and sync. Not supported: `thisAndFollowing`, search, creating video links, reminders, colors and a free/busy endpoint (calsdk computes free/busy from events).

## How it behaves

- **Discovery.** The provider finds the account's calendars from the server address, once per provider. `'primary'` is the server's default calendar for invitations, or else the first calendar that holds events. Task lists are not listed.
- **Ids.** A calendar id is the calendar's path, as `listCalendars` returns it. An event id is the name of its `.ics` file without the extension, normally its `UID`. Instances of a series are `<id>_<original start>`, the start being a UTC date-time (`20261103T100000Z`) or, for all-day series, a date (`20261103`).
- **Recurring events** are expanded by calsdk. Changing one instance stores an exception, deleting one adds an `EXDATE`. Changing a whole series through one of its instances moves the series by as much as that instance moved. When a series changes its start or its rule, exceptions for instances it no longer has are dropped.
- **Etags.** Updates and deletes send `ifMatch` to the server, and a stale one throws `ConflictError`. Every update is also conditional on the version just read, so a change made in between is never overwritten.
- **Video links.** calsdk cannot create one, but it reads a Meet, Teams or Zoom link from the event's URL, location or description into `conference`.
- **Attendees** are invited by the server, from the account's email address. `sendUpdates: 'none'` asks the server not to send invitations.
- **Sync** uses the server's sync tokens (RFC 6578). Each sync reports the single events, series and exceptions that changed, never computed occurrences. A token the server no longer accepts throws `SyncCursorExpiredError`.
- **Credentials** are only sent to the server's own origin and to the HTTPS host discovery finds the calendars on (iCloud keeps them on a host of their own). A redirect anywhere else fails.
- Files whose names do not end in `.ics` are skipped.

## Provider options

None. Events have no `providerMetadata`.
