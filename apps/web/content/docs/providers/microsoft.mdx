Use this provider for Outlook and Microsoft 365 calendars, on work, school and personal Microsoft accounts. It covers most of what Google does, with three differences you'll feel: Outlook stores recurrence as patterns rather than RRULEs, has no "this and following", and syncs a fixed window of time. Each is explained below, along with what calsdk does about it.

```npm
npm install calsdk @calsdk/microsoft
```

```ts
import { listEvents } from 'calsdk';
import { microsoft } from '@calsdk/microsoft';

const calendar = microsoft({ accessToken: () => getFreshAccessToken() });

const { events } = await listEvents({
  calendar,
  timeMin: '2026-11-01T00:00:00Z',
  timeMax: '2026-12-01T00:00:00Z',
});
```

## Credentials

`accessToken` is a Microsoft Graph token with `Calendars.ReadWrite`, or `Calendars.Read` if you only read. calsdk doesn't run the OAuth flow: get tokens from your auth library and pass a function that returns a fresh one. calsdk calls it before every request.

## Supports

All-day and recurring events (scopes `this` and `all`), attendees, Teams meetings on work and school accounts, one reminder per event, etags and sync. Not supported: `thisAndFollowing`, colors, search and a free/busy endpoint (calsdk computes free/busy from events).

## How it behaves

**Ids.** calsdk asks Graph for immutable ids, so an event keeps its id when it moves to another calendar and the ids you've stored stay valid.

**Time zones.** Events keep the zone they were scheduled in. Outlook names zones the Windows way ("Pacific Standard Time"), and calsdk turns those into IANA names.

**Recurrence.** Outlook stores patterns, not RRULEs. Rules with an exact Outlook pattern are converted both ways. Others, such as `RDATE`, `FREQ=HOURLY` or `BYMONTHDAY=31` alone, throw `UnsupportedFunctionalityError`, because saving them would quietly schedule a different set of meetings. One difference shows up when reading: Outlook moves a day a month lacks, such as the 31st, to the month's last day, so that rule reads back as `BYMONTHDAY=28,29,30,31;BYSETPOS=-1`.

**Deleted occurrences** read back as `EXDATE` lines on the series, which costs one extra request per series. Outlook keeps no list of excluded dates, only occurrences deleted one by one, so to exclude a new date, delete that occurrence instead of adding an `EXDATE`.

**`thisAndFollowing`** throws `UnsupportedFunctionalityError`. Moving one occurrence with scope `all` moves the series by the same wall-clock distance. On a monthly or yearly series that throws, since its pattern picks days by date and would land on different ones.

**Conditional deletes.** Outlook ignores `If-Match` on deletes, so `deleteEvent` with `ifMatch` compares the etag first. That leaves a small gap: a change made between the check and the delete isn't detected.

**Colors.** Outlook events have no color of their own, only categories, which carry Outlook's colors. `color` is ignored with a warning, so use the `categories` option instead.

**Reminders.** Outlook allows one popup reminder per event. It also has no default reminder to go back to, so `reminders: null` and `useDefault: true` leave the reminder unchanged, with a warning. To turn it off, pass `{ useDefault: false, overrides: [] }`.

**Teams meetings.** `createConference: true` asks for a Teams meeting. Personal accounts can't create one through Graph, so the event is saved without it and the result carries a warning.

**`sendUpdates`.** Outlook always notifies attendees, so values other than `'all'` return a warning.

**Search** throws `UnsupportedFunctionalityError`. Filter the listed events instead.

**Sync** uses Graph delta queries, which work over a date range. So a sync covers a fixed window, by default one year back and two years ahead of the first sync, and the cursor keeps it. Changes cover single events, series and changed occurrences. Deleting one occurrence changes its series, so it arrives as an update of the series with a new `EXDATE`.

## Provider options

```ts
await createEvent({
  calendar,
  event,
  providerOptions: {
    microsoft: { showAs: 'oof', importance: 'high', categories: ['Travel'], transactionId: 'trip-42' },
  },
});

await syncEvents({
  calendar,
  providerOptions: {
    microsoft: { timeMin: '2026-01-01T00:00:00Z', timeMax: '2027-01-01T00:00:00Z' },
  },
});
```

| Function                     | Option          | Type |
| ---------------------------- | --------------- | ---- |
| `createEvent`, `updateEvent` | `showAs`        | `'free' \| 'tentative' \| 'busy' \| 'oof' \| 'workingElsewhere'`. Overrides `showAs` on the event |
| `createEvent`, `updateEvent` | `importance`    | `'low' \| 'normal' \| 'high'` |
| `createEvent`, `updateEvent` | `categories`    | `string[]`, Outlook category names. Categories carry Outlook's colors |
| `createEvent`, `updateEvent` | `transactionId` | `string`. Makes a create safe to retry: Outlook will not create it twice |
| `syncEvents`                 | `timeMin`, `timeMax` | ISO 8601 instants with an offset. The window a first sync covers |
