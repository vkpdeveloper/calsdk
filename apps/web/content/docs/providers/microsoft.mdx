The Microsoft provider works with work, school and personal Microsoft accounts. Coverage is close to [Google's](/docs/providers/google), with three differences you'll feel: Outlook stores recurrence as [patterns](https://learn.microsoft.com/graph/api/resources/patternedrecurrence) rather than RRULEs, has no "this and following", and [syncs a fixed window](https://learn.microsoft.com/graph/api/event-delta) of time.

```npm
npm install @cal-sdk/core @cal-sdk/microsoft
```

```ts
import { listEvents } from '@cal-sdk/core';
import { microsoft } from '@cal-sdk/microsoft';

const calendar = microsoft({ accessToken: () => getFreshAccessToken() });

const { events } = await listEvents({
  calendar,
  timeMin: '2026-11-01T00:00:00Z',
  timeMax: '2026-12-01T00:00:00Z',
});
```

## Credentials

`accessToken` is a Microsoft Graph token with the [permission](https://learn.microsoft.com/graph/permissions-reference) `Calendars.ReadWrite`, or `Calendars.Read` if you only read. calsdk doesn't run the OAuth flow: get tokens from your auth library and pass a function that returns a fresh one. calsdk calls it before every request.

## What does Outlook not support in calsdk?

On Outlook, calsdk doesn't support `thisAndFollowing`, event colors or search, and it computes free/busy from events instead of calling a free/busy endpoint. Search throws `UnsupportedFunctionalityError`, so filter the listed events instead. See the [comparison](/docs/providers) for every provider.

## Outlook behavior

### Recurrence patterns

Outlook stores recurrence as [patterns](https://learn.microsoft.com/graph/api/resources/patternedrecurrence), not RRULEs. Rules with an exact Outlook pattern are converted both ways. Others, such as `RDATE`, `FREQ=HOURLY` or `BYMONTHDAY=31` alone, throw `UnsupportedFunctionalityError`, because saving them would quietly schedule a different set of meetings. One difference shows up when reading: Outlook moves a day a month lacks, such as the 31st, to the month's last day, so that rule reads back as `BYMONTHDAY=28,29,30,31;BYSETPOS=-1`.

Outlook also keeps no list of excluded dates, only [occurrences deleted one by one](https://learn.microsoft.com/graph/api/resources/event). calsdk reads those back as `EXDATE` lines on the series, which costs one extra request per series. To exclude a new date, delete that occurrence instead of adding an `EXDATE`.

### No "this and following"

`thisAndFollowing` throws `UnsupportedFunctionalityError` on Outlook. You can still move a whole series from one of its occurrences: with scope `all`, the series moves by the same wall-clock distance. On a monthly or yearly series that throws too, since its pattern picks days by date and would land on different ones. [Recurring events](/docs/guides/recurring-events) shows the scopes on every provider.

### How far back and ahead does Outlook sync?

By default, an Outlook sync covers one year back and two years ahead of the first sync, and the cursor keeps that window. The window is fixed because calsdk [syncs](/docs/guides/sync) Outlook with Graph [delta queries](https://learn.microsoft.com/graph/api/event-delta), which work over a date range.

Pass `timeMin` and `timeMax` in the provider options to choose another window. Changes cover single events, series and changed occurrences. Deleting one occurrence changes its series, so it arrives as an update of the series with a new `EXDATE`.

### Ids and time zones

calsdk asks Graph for [immutable ids](https://learn.microsoft.com/graph/outlook-immutable-id), so an event keeps its id when someone moves it to another calendar, and the ids you've stored stay valid. Times keep the zone they were scheduled in; Outlook names zones the Windows way ("Pacific Standard Time"), and calsdk turns those into IANA names, as [Time zones](/docs/concepts/time-zones) describes.

### Writing events

Outlook ignores `If-Match` on [deletes](https://learn.microsoft.com/graph/api/event-delete), so `deleteEvent` with `ifMatch` compares the etag first. That leaves a small gap: a change made between the check and the delete isn't detected.

`createConference: true` asks for a Teams meeting. Graph [adds Teams meetings](https://learn.microsoft.com/graph/outlook-calendar-online-meetings) only where Teams comes with a Microsoft 365 business or enterprise plan, so personal accounts, and some work accounts, can't get one. On those accounts the event is saved without it, and the result carries a warning. Outlook also always notifies attendees, so `sendUpdates` values other than `'all'` return a warning.

Outlook allows [one popup reminder](https://learn.microsoft.com/graph/api/resources/event) per event, and it has no default reminder to go back to. So `reminders: null` and `useDefault: true` leave the reminder unchanged, with a warning. To turn it off, pass `{ useDefault: false, overrides: [] }`. Events have no color of their own either, only [categories](https://learn.microsoft.com/graph/api/resources/outlookcategory), which carry Outlook's colors. `color` is ignored with a warning, so use the `categories` option instead.

## Provider options

```ts
await createEvent({
  calendar,
  event,
  providerOptions: {
    microsoft: { showAs: 'oof', importance: 'high', categories: ['Travel'], transactionId: 'trip-42' },
  },
});

await syncEvents({
  calendar,
  providerOptions: {
    microsoft: { timeMin: '2026-01-01T00:00:00Z', timeMax: '2027-01-01T00:00:00Z' },
  },
});
```
