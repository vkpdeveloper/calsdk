Use this provider when the meeting itself is the thing you're scheduling: a sales call, a client check-in, a weekly office hour. Zoom's scheduled meetings are the events, and every one has its Zoom link in `conference`. Recurring meetings work, within the [patterns Zoom supports](https://developers.zoom.us/docs/api/meetings/). All-day events aren't supported, and listing is slower than you'd expect.

```npm
npm install @cal-sdk/core @cal-sdk/zoom
```

```ts
import { createEvent } from '@cal-sdk/core';
import { zoom } from '@cal-sdk/zoom';

const calendar = zoom({ accessToken: () => getFreshAccessToken() });

const { event } = await createEvent({
  calendar,
  event: {
    title: 'Planning',
    start: { dateTime: '2026-11-03T10:00:00', timeZone: 'Europe/Berlin' },
    end: { dateTime: '2026-11-03T10:45:00', timeZone: 'Europe/Berlin' },
    recurrence: ['RRULE:FREQ=WEEKLY;COUNT=6'],
  },
});

event.conference?.joinUrl; // 'https://zoom.us/j/...'
```

## Credentials

`accessToken` is a Zoom OAuth access token with the scopes `meeting:read` and `meeting:write`. With [granular scopes](https://developers.zoom.us/docs/integrations/oauth-scopes-granular/): `meeting:read:meeting`, `meeting:read:list_meetings`, `meeting:write:meeting`, `meeting:update:meeting`, `meeting:delete:meeting` and `user:read:user`.

For your own account, a [Server-to-Server OAuth](https://developers.zoom.us/docs/internal-apps/s2s-oauth/) app is the simplest route. Its tokens last an hour, so pass a function that mints and caches them. calsdk asks it for a token before each request:

```ts
let cached: { token: string; expires: number } | undefined;

const calendar = zoom({
  accessToken: async () => {
    if (cached && cached.expires > Date.now()) return cached.token;
    const response = await fetch(
      `https://zoom.us/oauth/token?grant_type=account_credentials&account_id=${ZOOM_ACCOUNT_ID}`,
      {
        method: 'POST',
        headers: { Authorization: `Basic ${btoa(`${ZOOM_CLIENT_ID}:${ZOOM_CLIENT_SECRET}`)}` },
      },
    );
    const { access_token, expires_in } = await response.json();
    cached = { token: access_token, expires: Date.now() + (expires_in - 60) * 1000 };
    return access_token;
  },
});
```

## What does calsdk not support on Zoom?

All-day events, `thisAndFollowing`, `ifMatch` and search throw `UnsupportedFunctionalityError`. Free/busy is computed from meetings. See the [comparison](/docs/providers) for every provider.

`location`, `visibility`, `reminders` and `color` are ignored with a [warning](/docs/concepts/warnings), since a [Zoom meeting](https://developers.zoom.us/docs/api/meetings/) takes place at its link, has no visibility or color, and gets the reminders the account is set up with.

## Zoom behavior

### Which recurring meetings can Zoom schedule?

Zoom [repeats meetings](https://developers.zoom.us/docs/api/meetings/) daily, weekly on set weekdays, or monthly on a day of the month or an nth weekday, for up to 60 meetings or until a date:

| Repeats | Days                                 | Interval       |
| ------- | ------------------------------------ | -------------- |
| Daily   | Every day                            | 1 to 99 days   |
| Weekly  | Set weekdays                         | 1 to 50 weeks  |
| Monthly | A day of the month or an nth weekday | 1 to 10 months |

Other rules throw `UnsupportedFunctionalityError` rather than saving a different schedule, as do rules whose days leave out the first meeting. Zoom's weeks start on Monday, the [RFC 5545](https://datatracker.ietf.org/doc/html/rfc5545#section-3.3.10) default, so a rule repeating every few weeks on several days with another `WKST` throws too. Zoom's [recurrence settings](https://developers.zoom.us/docs/api/meetings/) keep no list of excluded dates: delete occurrences one by one instead of passing `EXDATE` lines. [Recurring events](/docs/guides/recurring-events) covers the same rules on other providers.

Zoom lists a series' meetings as its [`occurrences`](https://developers.zoom.us/docs/api/meetings/), and that list is empty for a series that starts far enough ahead. calsdk refuses such a series, because it would have nothing to show. Creating one, or moving a meeting or series that far, throws `UnsupportedFunctionalityError`, and calsdk deletes what Zoom created or undoes the change.

You can only move or resize one occurrence on its own. Other changes need `scope: 'all'`, which changes the whole series, and moving an occurrence with `scope: 'all'` moves the series by as much. calsdk moves a series by sending Zoom its whole [`recurrence`](https://developers.zoom.us/docs/api/meetings/) again, and Zoom then schedules every meeting of it anew, so occurrences you deleted, moved or resized on their own come back as they were, with ids for their new starts. The update returns a warning when that happens, so you can tell your user.

### Calendars, ids and times

`'primary'` holds the meetings the user hosts, and its time zone is the user's Zoom time zone. An event id is the meeting id. An occurrence of a series is `<meeting id>_<original start in UTC>`, such as `84512345678_20261103T090000Z`. Times are shown in the time zone the meeting was scheduled in, and meetings last whole minutes, up to [24 hours](https://developers.zoom.us/docs/api/meetings/).

### Invitees

Attendees are Zoom's [meeting invitees](https://developers.zoom.us/docs/api/meetings/), by email address only. `getEvent` returns them with the host as `organizer`. Listing and sync leave `attendees` and `organizer` out, as Zoom doesn't list them. Zoom doesn't email invitees about changes made through its API, so `sendUpdates` values other than `'none'` return a warning.

### Listing and sync

Listing reads every scheduled meeting and filters them, since Zoom can't list meetings by time. Each series takes a request of its own, made one at a time to stay under Zoom's [rate limits](https://developers.zoom.us/docs/api/rate-limits/), so an account with many recurring meetings lists slowly. Zoom also [cuts agendas in listings](https://developers.zoom.us/docs/api/meetings/) to 250 characters and stops listing meetings some time after they end.

Zoom's [meeting list](https://developers.zoom.us/docs/api/meetings/) can't select meetings by when they changed either, so each [sync](/docs/guides/sync) reads every meeting and compares it with the last sync. All changes come on one page. Meetings Zoom stops listing after they end aren't reported as deleted.

## Metadata [#event-fields]

Zoom has no provider options. Events carry `providerMetadata.zoom`:

| Field          | Type and notes |
| -------------- | ---- |
| `uuid`         | `string`, which Zoom uses for past meetings and recordings |
| `occurrenceId` | `string`, Zoom's `occurrence_id`, on occurrences of a series |
