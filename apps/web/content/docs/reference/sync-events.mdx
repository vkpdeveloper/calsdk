---
title: syncEvents
metaTitle: "syncEvents: incremental calendar sync with a cursor"
description: syncEvents returns every event created, changed or deleted in a calendar since a stored cursor, so you can keep a local copy up to date.
---

The first call returns what the provider syncs, and each later call returns what changed since the cursor you pass. Save the new cursor after applying the changes to your copy, such as a table in Postgres. Outlook syncs a fixed window, because Microsoft Graph runs [delta queries on a date range](https://learn.microsoft.com/en-us/graph/delta-query-events). [Sync changes](/docs/guides/sync#how-each-provider-syncs) covers how much each provider fetches.

```ts
import { syncEvents } from '@cal-sdk/core';

const { changes, nextCursor } = await syncEvents({ calendar, cursor: stored });
for (const change of changes) await apply(change);
await saveCursor(nextCursor);
```

## Result

<TypeTable
  type={{
    changes: { type: "({ type: 'upsert'; event: CalendarEvent } | { type: 'delete'; eventId: string })[]", description: 'Every change since `cursor`, in the order the provider returns them. Apply them in that order.', required: true },
    nextCursor: { type: 'string', description: 'Store it and pass it as `cursor` next time. Always present by default. With `paginate: false`, only on the last page.' },
    nextPageToken: { type: 'string', description: 'With `paginate: false`: more pages are left in this round.' },
    warnings: { type: 'Warning[]', required: true },
  }}
/>

Changes cover single events, series and exceptions, never computed occurrences.

## Throws

Both errors are listed with their fields in [Errors](/docs/reference/errors).

- `SyncCursorExpiredError` when the provider no longer accepts the cursor. Drop it, and your copy, and sync without one.
- `UnsupportedFunctionalityError` when the provider has no sync. Every built-in provider has it.
